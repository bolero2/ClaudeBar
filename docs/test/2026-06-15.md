## 1. 코드 분석 요약

### 1.1 프로젝트 개요
- **정체**: Claude Code CLI 세션을 모니터링·제어하는 **네이티브 macOS 메뉴바(SwiftUI) 에이전트 앱**. Swift, 7,630 LOC, 단일 바이너리(SPM) → `ClaudeDeck.app` 번들. 메뉴바 팝오버(380×500) + 대시보드 창(880×580) 두 표면이 하나의 `AppState`를 공유.
- **데이터 소스(모두 읽기)**: `~/.claude/projects/**/*.jsonl`(세션 트랜스크립트), `~/.claude/claudedeck/status/*.json`(statusLine 캐시), `~/.claude.json`(MCP·계정), Keychain(OAuth 토큰), GitHub Releases, Anthropic OAuth usage API.
- **핵심 동작**:
  1. 세션 스캔/라이브 감지(트랜스크립트 mtime이 아닌 **statusLine 캐시 ts** 기반 — Claude Code 2.1.x 버퍼링 회피) → 라이브/종료, busy/waiting, 컨텍스트% 표시.
  2. **예약 입력 큐**: 세션이 *화면상* 유휴일 때만 프롬프트를 하나씩 타이핑+제출(포커스 비탈취). busy/선택형(권한·AskUserQuestion)/판독불가 시 주입 안 함.
  3. 세션 활성화(터미널 앞으로 / `claude --resume` 복구), kill, 새 세션, **종료 세션 삭제(멀티셀렉)**, **세션별 /remote-control 토글**, /compact·/clear, **전역 MCP 등록/토글**, 사용량·계정·설정, 자동 업데이트, 알림.

### 1.2 의존 관계
- `AppState`(중앙 컨트롤러) ← `SessionScanner`←`ProcessProbe`(ps/lsof)/`StatusCache`, `TerminalActivator`(AppleScript 화면판독·주입), `UsageService`/`OfficialUsageService`/`TokenManager`, `MCPService`/`ConfigStore`, `UpdateService`, `NotificationService`, `HotKeyManager`.
- 외부 의존: macOS AppleScript(Terminal/iTerm), Keychain(`security`), 네트워크(GitHub/Anthropic).

### 1.3 핵심 로직(결함 시 영향 큰 경로)
- **주입 게이팅**(`TerminalActivator.claudeScreenState` + `runQueueLoop`): 오판 시 작업 중 세션을 인터럽트하거나 질문에 잘못 응답 → 최우선 검증 대상.
- **라이브 세션 식별**(`attachLiveProcesses`): 오식별 시 엉뚱한 세션에 주입/컨텍스트 0% 표시.
- **MCP/config 쓰기**(`mutateConfig`): `~/.claude.json` 손상 시 Claude Code 전체 영향 → atomic+백업 검증.

### 1.4 데이터 흐름
`~/.claude` 파일 → 스캔/파싱 → `Session`/`Usage`/`MCP` 모델 → SwiftUI 뷰. 사용자 액션 → `AppState` → AppleScript(터미널 제어) / config 쓰기 / 알림.

### 1.5 테스트 대상 선정 근거
주입 게이팅·라이브 식별·config 쓰기가 가장 위험도 높음 → **실제 터미널/세션을 동원한 실동작 검증**에 집중. 나머지 UI는 실제 클릭+스크린샷 시각 검증. 파괴적(실데이터 삭제/설치/대화 비우기) 또는 외부 부수효과(토큰 회전) 항목은 throwaway 대상으로만 실행하거나 코드 검증으로 대체(아래 명시).

### 2.x 자체 검토
- **충분성**: 두 정독 에이전트로 전 파일을 읽어 ~50개 기능을 도출, 위 표가 전 기능을 커버. 핵심 위험 경로(주입 게이팅·라이브 식별·config 쓰기)는 실동작/E2E로 직접 검증.

- **연쇄 커버리지**: 주입 오판→대화 오염 경로를 `--test-screen`+`--screen`+`--queue-run`으로 교차 검증. 라이브 오식별→0% 표시 경로를 `--scan`으로 확인. config 쓰기→Claude Code 영향 경로를 무결성 diff로 확인.

## 3. 테스트 수행 상세

### 3.1 도구·명령
- 화면 판독: `screencapture -x -R <x,y,w,h>`(포인트 좌표 크롭) → 직접 시각 판독.
- 클릭: `osascript -e 'tell application "System Events" to click at {x,y}'`(포인트). 사이드바 등 큰 타깃은 안정적. SwiftUI는 AX 트리를 거의 노출하지 않아 작은 텍스트필드 좌표 클릭은 불안정 → 상태변경은 프로덕션 동일 코드의 진단 CLI/백엔드로 검증.
- 진단 CLI(실동작): `--test-screen --test-queue --test-inject --scan --probe --screen <tty> --queue-run <cwd> <n> <text> --raise <tty> --check-update --notify-test`.
- 빌드: `swift build -c release` → `.build/release/ClaudeDeck` 및 `ClaudeDeck.app/Contents/MacOS/ClaudeDeck`.

### 3.2 더미 데이터 / E2E 셋업
- throwaway 라이브 세션: `mkdir /tmp/cdqa` → Terminal에서 `cd /tmp/cdqa && claude --dangerously-skip-permissions`(신뢰 프롬프트 없이 idle 입력창 도달, tty=ttys000, 세션 11f40e52).
- 주입 프롬프트: `"Reply with exactly the single word PONG and nothing else."` ×2(무해, 토큰 최소).
- Teardown: throwaway claude(pid) kill, 터미널 창 닫기, `/tmp/cdqa`·프로젝트 jsonl·statusLine 캐시 제거 → `--scan`에 내 세션만 남음 확인. `~/.claude.json`은 사전 백업.

### 3.3 절차
1. 전 코드 정독(에이전트 2 + Diagnostics.swift 직독) → 기능/안전맵 도출.
2. 안전 진단(B-4,D-1,B-5,F-6) → 9/9·9/9·정확·버전.
3. 실주입(D-3) `--test-inject` → 실행+포커스 유지 PASS.
4. GUI: 메뉴바 클릭→팝오버, `--dashboard`로 안정 창→5탭 클릭 캡처(A,C,E,F 시각).
5. **안전 사고 대응**: 대시보드에서 현재 세션에 armed 큐 발견 → arm 해제 후 재시작·미재무장 확인(OBS-1).

## 5. 종합 의견

### 5.1 코드 품질
- 위험 경로(주입)가 **2신호 게이팅**(화면 마커 + 프로세스 CPU 교차)과 **선택형 차단**으로 보수적으로 설계됨. 실제 라이브 세션 E2E에서 busy 중 대기→유휴 시에만 주입이 정확히 동작(D-2). 포커스 비탈취도 실증(D-3).
- config 쓰기는 atomic+롤링 백업, 라이브 식별은 캐시 기반으로 2.1.x 버퍼링을 우회 — 견고.
- 민감정보(API 키)는 추출/로깅 안 함, 토큰은 actor로 직렬화. 보안 측면 양호.

### 5.2 잠재 위험
1. **OBS-1**(최우선): 현재 사용 중 세션 자동 재무장 → 작업 대화에 의도치 않은 주입 가능. 활성 세션 가드 권고.
2. 라이브 식별이 statusLine 헬퍼 설치 전제. 미설치 시 newest-by-mtime 폴백이라 같은 cwd 다중 세션에서 오식별 가능(코드상 폴백 명시됨).
3. `/remote-control` 명령 문법이 미확정 가정 → 실제 Claude 명령과 불일치 시 무효 입력.

### 5.3 향후 필요한 테스트 영역
- 멀티셀렉 삭제/compact/clear/remote-control/언어토글의 **실제 GUI 실행**(throwaway 세션 + 안정적 UI 자동화 도입: 예 `cliclick` 설치 또는 SwiftUI 접근성 라벨 부여로 AX 클릭 가능화).
- 알림 평가기의 시간의존 로직(대기 10s 디바운스, 컨텍스트 교차) 실시간 시뮬레이션.
- iTerm 경로(현재 Apple_Terminal로 검증) 주입·화면판독.
- 자동 업데이트 스왑을 격리 환경(복제 번들)에서 실제 실행.

### 5.4 결론
**실행한 전 항목 PASS, 크래시·데이터 유실 없음.** 플래그십 기능(게이팅 예약 주입)은 실제 라이브 claude 세션에서 E2E로 검증됨. 개선 권고는 OBS-1(활성 세션 자동 재무장 가드) 1건이 우선이며, 나머지는 경미하거나 비배포 경로.
