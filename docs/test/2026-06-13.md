### 1. 코드 분석 요약

#### 프로젝트 개요
여러 Claude Code 세션을 메뉴바에서 관리하는 네이티브 앱. `NSStatusItem`+`NSPopover`로 팝오버 UI를 띄우고, `AppState`(@MainActor ObservableObject)가 세션(5s)·사용량/한도(60s)를 주기적으로 집계한다. 데이터 소스는 `~/.claude/projects/<dir>/<id>.jsonl`(세션), `ps`/`lsof`(라이브 프로세스), `~/.claude.json`(MCP·계정), Keychain OAuth(공식 사용량). 외부 의존성 0.

#### 테스트 대상 선정 이유
- **신규 위험 경로**: `/compact`·`/clear`는 사용자의 실제 세션 터미널에 텍스트를 주입하므로(부작용 가능) 명령 생성·이스케이프·주입 경로가 정확해야 한다.
- **상태 전환 위험**: 대시보드는 `.accessory ↔ .regular` activation policy를 토글한다 — 잘못되면 Dock/포커스/메뉴바 에이전트 상태가 깨질 수 있다.
- **영속성**: compact 템플릿은 JSON으로 UserDefaults에 저장 — 인코딩/디코딩 라운드트립 무결성이 중요.
- **회귀**: 팝오버를 NSStatusItem로 쓰는 기존 5탭이 깨지지 않았는지.

### 2. 테스트 계획

#### 계획 수립 배경
GUI 메뉴바 앱이라 별도 테스트 타깃이 없다. 따라서 (a) 순수 로직은 동일 코드를 복제한 **독립 Swift 하니스**로 단위 검증, (b) 주입/터미널 제어는 **실제 세션을 건드리지 않는 임시 터미널 격리 통합 테스트**, (c) 윈도우/정책 전환은 **번들 실행 + 런타임 self-test**, (d) 렌더링은 **mock 데이터 ImageRenderer**로 검증한다. 안전성을 위해 어떤 테스트도 실제 Claude 세션·실데이터를 변경하지 않는다.

#### 테스트 계획 자체 검토 결과
- **충분성**: 신규 3기능(주입/템플릿/대시보드) + 아이콘 + 기존 5탭 회귀를 모두 포함. 순수 로직·부작용·상태전환·렌더·실데이터 파이프라인을 각각 다른 계층으로 커버.
- **안전성**: 주입 테스트는 전용 임시 Terminal 창에만 수행하고 종료 후 창을 닫고 임시파일 삭제. 실제 Claude 세션·`~/.claude`·UserDefaults를 변경하지 않음. `--notify-test`만 사용자 알림센터에 1건 발송(무해, 아이콘 확인 목적).
- **연쇄 커버리지**: 주입 명령 생성(1) → 개행 접기(2) → 이스케이프(3) → 실제 주입(5,6)의 연쇄를 순차 검증. 대시보드 정책 전환(7)이 메뉴바 에이전트 상태로 안전 복귀하는지까지 추적.

### 5. 종합 의견

- **품질**: 신규 3기능 + 아이콘 모두 의도대로 동작. 부작용 경로(터미널 주입)는 명령 생성→이스케이프→실제 실행까지 연쇄 검증으로 안전성 확인. 대시보드 정책 전환은 open=.regular/close=.accessory로 깔끔히 복귀.
- **잠재 위험**:
  1. `/compact`·`/clear`는 **세션이 대기(프롬프트) 상태**일 때만 의도대로 제출됨 — busy 세션에선 Claude가 입력을 큐잉. 현재 메뉴는 라이브 세션 전체에 노출되므로, 향후 busy일 때 비활성/경고 UX를 고려할 만함.
  2. 대시보드 `.regular` 동안 앱 메인 메뉴가 없어 `⌘W` 미동작(빨간 닫기 버튼은 정상). 최소 메뉴 추가 검토 가치 있음.
- **향후 테스트 영역**: 실제 대기 세션에 대한 수동 `/compact` 1회 확인(사용자), 알림/Dock 아이콘 육안 확인, iTerm2 경로의 `write text` 주입 실기기 확인(현재 Apple Terminal 경로만 격리 검증).
