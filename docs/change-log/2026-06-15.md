## [ADD] 원격(SSH) 세션 표시 + 접속 — 무설치 인라인 프로브

### 배경

ClaudeDeck는 로컬 `~/.claude`와 로컬 `ps`만 읽어, 사용자가 `ssh 3090f` 등 사내 서버에 접속해 실행한 claude 세션은 전혀 보이지 않았다. 원격 서버에는 아무것도 설치하지 않는다는 제약 아래, 등록한 SSH 호스트의 claude 세션을 로컬 세션과 함께 표시하고, 클릭 시 그 세션에 접속할 수 있게 한다.

### 동작 방식

- **무설치 인라인 SSH 프로브**: 새로고침마다 `ssh <host> python3 -`로 파이썬 프로브를 stdin 주입 실행해 세션 요약(JSON)을 받는다. 원격엔 아무것도 안 깔리고, ControlMaster(`ControlPersist=60s`)로 연결을 재사용해 지연을 줄인다. 메타데이터(모델/브랜치/토큰수/permission/활동)만 추출하고 transcript 본문·비밀은 다루지 않는다.
- 프로브는 로컬 `SessionScanner.parseTail` + 라이브 조인을 포팅: `~/.claude/projects/*/`의 최근 JSONL tail 파싱 + `ps`/`readlink /proc/<pid>/cwd`로 라이브 매칭(프로세스의 실제 cwd ↔ transcript cwd 비교, 인코딩 우회). 컨텍스트 >200K면 1M 자동 판정.
- **JSONL이 아직 없는 새 세션**(브랜드뉴/버퍼링)은 라이브 프로세스(+cwd)로 행을 합성(`resumable=false`). 첫 메시지로 JSONL이 생기면 실제 id를 가진 resumable 세션으로 교체된다.
- **호스트 단위 등록**: 설정 "원격 호스트" 섹션이 `~/.ssh/config`의 Host 별칭을 토글로 보여주고(수동 추가 가능), 켠 호스트는 `AppSettings.remoteHosts`에 영속. 호스트 1회 등록으로 그 호스트의 모든 세션이 자동 발견된다.
- **클릭 동작**: 로컬에 그 호스트로 ssh 접속 중인 탭이 있으면 그 탭을 앞으로(`ProcessProbe.remoteSSHProcess`), 없으면 새 터미널에서 `ssh -t <host> 'cd <cwd> && claude --resume <id>'`. 합성 행은 id가 없어 `--resume` 없이 접속.
- **새로고침 깜빡임 방지**: 로컬을 먼저 표시하되 직전 원격 결과(`lastRemoteSessions`)를 유지하다가 새 프로브 완료 시 교체. 호스트별 병렬 프로브 + 타임아웃으로 오프라인 호스트가 로컬 표시를 막지 않음.
- UI: 목록을 "실행 중" 바로 아래에 호스트별 "원격: <host>" 섹션으로 배치, 파란 호스트 배지·라이브/1M/BYPASS 표시. 원격 행은 읽기 전용(접속/ssh 명령 복사/경로 복사)이며 로컬 전용 동작(앞으로/주입/kill/삭제)은 숨김.

### 구현

- 신규 `Services/RemoteScanner.swift`(인라인 파이썬 프로브 + 디코딩), `Services/SSHConfig.swift`(`~/.ssh/config` 파싱).
- `Core/Shell.swift`: `runWithStdin`(stdin 주입 + 타임아웃 적용).
- `Core/Models.swift`: `Session.remoteHost`, `isLive`.
- `Core/Settings.swift`: `remoteHosts` 영속 + 토글 헬퍼.
- `Services/ProcessProbe.swift`: `remoteSSHProcess(forHost:)`(로컬 ssh 탭 탐지).
- `Services/TerminalActivator.swift`: `bringToFront`(앞으로 전용 분리), `openRemoteResume`.
- `AppState.swift`: `refreshSessions` 원격 병합/깜빡임 방지, `activate` 원격 분기, `copyRemoteResumeCommand`.
- `Features/SessionListView.swift`·`SettingsView.swift`·`Core/Loc.swift`: 원격 섹션/배지/메뉴, 설정 호스트 토글, 문자열.

### 검증

- `swift build` 통과. 앱이 3090f에 실제 SSH 접속(ControlMaster 소켓·mux 프로세스 확인). resume 명령 인용 부호 검증.

### 향후(범위 밖)

- 같은 호스트 다중 세션의 정확한 탭 매칭(현재는 호스트 단위), 원격 슬래시 주입, IP 직접 접속 시 별칭 매칭.

## [FIX] 강제 종료(Command+Q)된 세션 재진입 불가 — 복구 불가 감지 + 폴백 + 안전 종료

### 문제

Claude Code가 실행 중인 터미널을 **Command+Q로 강제 종료**한 뒤 ClaudeDeck에서 재진입하면 다음 에러로 막다른 길에 빠짐:

```
No conversation found with session ID: 5dd79110-...
```

### 원인 (직접 검증)

- 문제 세션의 JSONL(`~/.claude/projects/.../<id>.jsonl`)에는 **`ai-title` 스텁 한 줄(117 bytes)** 만 있고 user/assistant 대화 레코드가 **0개**. statusline 캐시상 73,287 토큰까지 쌓였던 대화인데도 디스크엔 없음.
- **현재 실행 중인 라이브 세션조차** 활발히 작업하는 2분 동안 transcript가 디스크에 전혀 안 써짐(`find -mmin -2` 0건)을 확인.
- 즉 **Claude Code 2.1.x는 대화를 메모리에 버퍼링하다가 정상 종료(`/exit`·Ctrl-D) 시점에만 통째로 flush**. Command+Q는 `claude`를 flush 전에 SIGHUP/SIGKILL로 죽이므로 대화 본문이 영구 유실되고 `ai-title` 스텁만 남음.
- `claude --resume`는 대화 메시지를 요구하므로 정당하게 실패. ClaudeDeck이 잘못된 ID를 넘긴 게 아니라, **그 세션의 대화가 디스크에 존재하지 않아 복구가 물리적으로 불가능**한 상태였음.

유실된 대화를 되살릴 방법은 없으므로, (1) 복구 불가 세션을 **감지**해 정직하게 처리하고, (2) 유실 자체를 줄이는 **예방** 액션을 추가.

### 변경 사항

**1) 복구 불가 감지 + 폴백**
- `Session.resumable: Bool` 추가. JSONL tail에 user/assistant 레코드가 하나라도 있으면 `true`, 스텁만 있으면 `false`.
- `SessionScanner.parseTail`이 `hasConversation`을 함께 반환 → enrich 대상(top 40) 세션에 반영.
- `AppState.activate()`: 종료된 세션 클릭 시 `resumable`이면 기존 `claude --resume`, **아니면 같은 cwd/모델/1M/권한모드로 새 `claude` 세션**(`TerminalActivator.openFresh`)을 열어 막다른 에러 대신 바로 작업 가능한 터미널 제공.
- `TerminalActivator`: `--model`/권한 플래그 빌드를 `sessionFlags()`로 공통화하고 `openFresh()` 추가.
- UI: 종료 + 복구 불가 행에 주황색 **`복구 불가` 배지**, hover 도움말/우클릭 라벨을 `새 세션 시작 (복구 불가)`로 정직하게 표기.

**2) 예방 — 안전 종료**
- 라이브 세션 우클릭 메뉴에 **`안전 종료 (저장 후 종료)`** 추가. tty에 `/exit`를 주입해 Claude Code가 transcript를 flush한 뒤 종료 → 이후 정상 resume 가능. (`AppState.safeQuit`)
- Command+Q / `kill`(SIGTERM)은 flush를 보장하지 않으므로, 세션을 보존하려면 안전 종료 사용을 안내.

### 검증

- `swift build` 통과.
- 분류 로직 실데이터 대조: 강제종료 스텁 → `hasConversation=False`(복구 불가), 정상 세션(50KB+) → `True`(복구 가능) 확인.

### 이슈/논의

- 근본 원인은 Claude Code 2.x의 transcript 버퍼링 동작 + 터미널 Command+Q의 강제 종료 시그널. ClaudeDeck은 유실 데이터를 복원할 수 없어 **감지·폴백·예방**까지가 한계. 사용자에게 "세션을 보존하려면 `/exit` 또는 안전 종료" 가이드 필요.
- `kill`(SIGTERM)이 flush를 트리거하는지 여부는 별도 확인 과제(현재는 미보장 가정).
