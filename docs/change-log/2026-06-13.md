## [ADD] 세션에서 `/compact` · `/clear` 실행 (저장 문구 템플릿)

세션 관리 앱답게, 실행 중 세션의 컨텍스트를 메뉴바에서 바로 압축/비울 수 있게 함. `/compact`는 (1) 기본, (2) 저장된 문구, (3) 즉석 입력 세 방식 중 선택.

### 동작 방식
- 라이브 세션의 tty를 찾아 해당 터미널 탭에 슬래시 명령을 **타이핑+제출**(사용자가 직접 입력하는 것과 동일). Apple Terminal은 `do script "<cmd>" in t`, iTerm2는 `tell s to write text`.
- 제약: 세션이 **프롬프트(대기) 상태**일 때 의도대로 동작. busy면 Claude Code가 입력을 큐잉.
- `/clear`는 대화를 비우는 파괴적 동작이라 **NSAlert 확인** 후 전송. `직접 입력` 압축도 NSAlert 입력 시트 사용.

### 저장 문구 템플릿
- `CompactTemplate`(id/name/prompt) 모델 추가, `AppSettings`에 JSON으로 영속화.
- 기본 프리셋 2개 내장: `종합 요약`(연속성 요약 프롬프트), `결정·미해결만`.
- 설정 탭에 템플릿 추가/이름·문구 편집/삭제 UI(`CompactTemplatesEditor`).

### 구현
- `Core/Models.swift`: `CompactTemplate` 추가.
- `Core/Settings.swift`: `compactTemplates` 영속화 + `defaultCompactTemplates` + add/update/delete.
- `Services/TerminalActivator.swift`: `sendText(_:text:)` + Apple Terminal/iTerm2 주입 스크립트(개행은 공백으로 접어 한 줄 제출).
- `AppState.swift`: `sendSlashCommand` / `compact(_:prompt:)` / `compactWithCustomPrompt` / `clearSession`.
- `Features/SessionListView.swift`: 라이브 세션 우클릭 메뉴에 `압축 (/compact)` 서브메뉴(기본·템플릿·직접입력) + `대화 비우기 (/clear)`.
- `Features/SettingsView.swift`: `compact 템플릿` 섹션.
- `Core/Loc.swift`: 관련 영문 문자열.

### 검증
- `swift build` 통과.
- 주입 경로를 **실제 세션 미접촉**으로 격리 검증: 임시 Terminal 창을 띄워 tty 매칭 → `do script "echo … in t"`로 명령이 그 탭에서 실제 실행됨을 확인(`CLAUDEBAR_INJECT_OK`) 후 창 정리. iTerm `write text`는 기존 `iTermOpenScript`에서 검증된 동일 verb.

## [ADD] 예약 입력 큐 (세션 유휴 시 프롬프트 자동 주입)

라이브 세션에 프롬프트를 여러 개 예약해두면, 세션이 **유휴(입력 대기) 상태가 될 때마다 하나씩 자동 주입**한다. `프롬프트 → 작업 → 다음 프롬프트 → …` 흐름으로, 긴 작업을 무인으로 이어 돌릴 수 있다. 주입은 **포커스를 뺏지 않고** 백그라운드 탭에 타이핑한다.

### 동작 방식
- 큐는 세션 id별로 영속화(`scheduledQueues`, JSON). **arm 상태(`runningQueues`)는 런타임 전용** — 재실행 시 초기화되어 예상치 못한 자동 주입을 방지.
- 새로고침 주기마다 `processPromptQueues`가 arm된 라이브 세션을 검사: `status == .waiting`(유휴)이고 **직전 주입 이후 새 활동이 관측된 경우에만** 다음 프롬프트를 1개 주입 → 같은 유휴 구간에서 중복 발사 방지(`queueLastInjection` 비교).
- 큐가 채워질 예정인 세션에는 **"입력 대기" 알림을 억제**(중복 알림 방지).
- 주입은 `TerminalActivator.injectText` — `sendText`와 달리 `activate`/창 재정렬 없이 tty 매칭 탭에만 타이핑(Apple Terminal `do script … in t`, iTerm2 `write text`).

### UI
- **대시보드 전용 편집기**(`PromptQueueEditor`): 프롬프트 추가/순서이동(↑↓)/삭제/비우기 + 시작·정지. 실행 중에는 편집 비활성화. 라이브 세션 행 아래 "예약 입력" 접이식 영역으로 노출(`queueEditable`).
- **팝오버 읽기 전용 배지**(`PromptQueueBadge`): 예약 개수 · 다음 프롬프트 미리보기 · 실행중 표시.

## [ADD] 유휴 감지 다중 신호화 — 화면 마커 + 프로세스 CPU 교차 확인

화면 busy 마커(`esc to interrupt`/`· ↓↑`)는 Claude Code UI 문자열에 의존해, 버전이 바뀌면 깨질 수 있다. 가장 위험한 실패는 **작업중인데 유휴로 오판**(→ 응답 중 다음 프롬프트 주입 → 입력창 중복 누적 재발). 이를 막기 위해 CPU 신호를 보조 veto로 추가.

- `TerminalActivator.processBurningCPU(pid:)`: `ps -o cputime`로 누적 CPU 시간을 0.6초 간격 2회 샘플링해 코어 점유율 환산(%cpu의 decaying 평균 대신 정확한 델타). 8% 이상이면 "연산 중".
- `claudeScreenState`: 화면 마커가 **busy면 즉시 busy**(CPU 안 봄, 빠름). 화면이 **idle로 보일 때만** CPU 확인 → 스트리밍 중이면 busy로 덮어씀. 즉 마커가 깨져도 false-idle을 CPU가 잡음. 프로세스를 못 읽으면 false 반환(없는 프로세스가 busy를 강제하지 않음).
- 검증: 3세션에서 화면·CPU 신호 일치 — 작업중 세션(스트리밍) `screen=busy, cpu_busy=true`, 유휴 2세션 `idle, false`. CPU 샘플은 화면이 idle일 때만 들어가 비용 영향 최소.
- `--screen <tty>` 진단이 최종상태 + pid + cpu_busy를 함께 출력하도록 개편.

## [ADD] 예약 프롬프트 큐 — 실행 중 종료 시 재시작 후 자동 재개

예약 프롬프트 **텍스트**는 이미 `AppSettings.scheduledQueues`(UserDefaults JSON, 세션 id 키)로 영속화되어 종료-재시작 후에도 남아 있었다. 하지만 **주입 실행 상태**(`runningQueues`)는 런타임 전용으로 재시작 시 의도적으로 초기화되어, 자동 주입 중 앱이 종료되면 재시작 후 주입이 재개되지 않았다. 사용자 요구("실행 중에 종료되었다면 자동 재시작")에 맞춰 armed 상태를 영속화하고 재개 로직을 추가.

- `AppState.runningQueues`: `didSet`으로 `UserDefaults`(`armedQueues` 키, `[String]`)에 영속화. 큐가 비거나·세션 종료·사용자 중지 시 set에서 빠지므로, 진짜 in-flight 큐만 기록에 남는다.
- `resumeArmedQueues()`(앱 `start()`에서 호출): 영속된 armed 세션 id마다 재개 태스크 스폰.
- `resumeArmedQueue(_:graceSec:)`: 재시작 직후 첫 세션 스캔이 비동기이고 터미널도 기동 중일 수 있어, 해당 세션의 live 프로세스가 다시 발견될 때까지 grace window(기본 90초, 3초 폴링) 대기 → live면 `startQueue`로 재무장(루프 재스폰). 큐가 이미 비었거나 grace window 내 세션이 안 돌아오면 armed 플래그 제거. **세션이 여전히 live일 때만** 재개하므로 사용자가 안 띄운 세션엔 절대 주입하지 않는다.
- 세션 id는 JSONL 파일명(UUID)이라 재시작 후에도 안정적 → 영속된 큐가 동일 세션에 정확히 매칭된다. `claude --resume`도 같은 세션 id를 유지.
- 검증: `swift build` 성공. `--queue-run` 헤드리스 진단 경로는 `resumeArmedQueues`를 거치지 않아 영향 없음.

## [ADD] 최근 세션 삭제 — 박스 멀티셀렉 + 우클릭 (활성 세션 보호)

종료된 세션 기록(.jsonl)을 목록에서 직접 삭제. 실행 중(live) 세션은 삭제 대상에서 원천 제외 — 체크박스 자체가 안 뜨고, 우클릭 메뉴에도 삭제가 없으며, `deleteSessions`가 한 번 더 live를 필터링한다.

- `AppState.deleteSessions(_:)`: 종료 세션만 대상으로 확인 다이얼로그(개수 표시) → JSONL + statusLine 캐시(`StatusCache.dir/<id>.json`) 삭제 + 해당 세션의 예약 큐 정리(`stopQueue`/`clearQueue`) → `refreshSessions`. live 세션은 하드 가드로 제외.
- **박스 멀티셀렉**: "최근 세션" 헤더의 `선택` 버튼 → 각 행에 체크박스(원형 박스) 표시, 탭으로 선택 토글(이 모드에서 행 탭은 세션 활성화 대신 선택). `삭제 (N)` 버튼으로 일괄 삭제, `취소`로 모드 종료. 필터 전환 시 선택 자동 해제. 선택 행은 강조 배경.
- **우클릭 삭제**: 종료 세션 컨텍스트 메뉴 하단에 `세션 삭제`(destructive) 추가 — 즐겨찾기로 고정된 종료 세션도 우클릭으로 삭제 가능.
- 선택 모드 중에는 종료 행의 grayscale 뮤트 해제(체크박스 가독성).
- `Loc`: "세션 삭제"/"선택"/"삭제"/확인 문구 한·영 추가.
