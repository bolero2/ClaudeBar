## [ADD] Claude Bar v1 — macOS 메뉴바 앱 (수직 슬라이스)

여러 Claude Code 세션을 메뉴바에서 관리하는 네이티브 SwiftUI 앱 초기 구현.

### 기술 결정
- 기술 스택: **Native Swift (SwiftUI `MenuBarExtra`)** — 프로세스 조회/AppleScript/Keychain 접근이 네이티브로 자연스럽고 번들이 가벼움.
- 사용량 소스: **로컬 JSONL 집계 우선 + 공식 엔드포인트 폴백(스텁)**.
- 범위: 4탭(세션·사용량·MCP·계정) 읽기 전용 수직 슬라이스.

### 구현
- 진입점/셸: `App.swift`(@main, Dock 숨김), `AppState.swift`(5초 자동 새로고침), `Diagnostics.swift`(`--probe` 자가 점검)
- Core: `ClaudePaths`, `Models`, `ConfigStore`(`~/.claude.json` 파싱), `Shell`(ps/lsof/osascript 래퍼)
- Services
  - `SessionScanner` — `~/.claude/projects` 스캔, JSONL tail에서 model/branch/cwd 추출
  - `ProcessProbe` — `ps`/`lsof`로 라이브 `claude` 프로세스 탐지, `TERM_PROGRAM`/`TERM_SESSION_ID`만 추출(비밀 미저장)
  - `TerminalActivator` — tty 매칭 AppleScript로 Apple Terminal/iTerm2 탭 활성화
  - `UsageService` — JSONL `usage` 레코드 5h/7day 시간창 집계
- Features: `RootView`(탭 컨테이너) + `SessionListView`/`UsageView`/`MCPView`/`AccountView`, `Format`

### 검증 (`--probe`, 실제 `~/.claude` 데이터)
- 세션 59개 인식, 라이브 세션 1개를 `[진행 중]`으로 정확히 매칭
- 사용량 5h/7day 집계 정상, MCP(전역 1·프로젝트 1)·계정 정상 출력

### 해결한 이슈
- **라이브 프로세스 미탐지**: `ps` 컬럼 패딩(2칸 공백)으로 `maxSplits` 마지막 조각에 선행 공백이 남아 매칭 실패 → comm 트림으로 수정.
- **하이픈 경로 cwd 오매칭**: 폴더명 디코딩이 `claude-bar` → `claude/bar`로 손실 발생 → 매칭은 무손실 인코딩(`encodeCwd`) 역방향으로, 표시 cwd는 JSONL 실제 값으로 수정.

## [FIX] 사용량 탭이 비어 보이는 문제

증상: `.app` 실행 후 사용량 탭을 열면 비어 있음.

근본 원인 2가지 (진단: 오프스크린 렌더 + 런타임 stderr 로깅으로 추적)
1. **데이터 로딩 시점**: `state.start()`를 `MenuBarExtra` 콘텐츠의 `.onAppear`에서 호출 → 팝오버를 처음 열 때만 시작됨. `AppDelegate.applicationDidFinishLaunching`에서 시작하도록 이동(+ 1회 실행 guard, `AppState.shared`).
2. **집계 속도**: 30일치 JSONL을 매번 `JSONSerialization`으로 전체 파싱 → 약 10–17초 소요. 열자마자 보면 아직 `nil`.

성능 재작성 (`UsageService`)
- **바이트(UTF-8) 레벨 스캔**: Swift `String`의 유니코드 연산(`range(of:)`·`contains`·`.isNumber`)이 수 MB에서 매우 느림 → 원시 바이트로 키/정수 추출.
- **ISO UTC 타임스탬프 문자열 비교**: 사전식 정렬이 곧 시간순 → 시간창 판정에 `Date` 파싱 제거(19자 prefix 비교, 일별은 10자 prefix 버킷).
- **파일별 mtime 캐시**: 안 바뀐 파일 재파싱 제거.
- 결과: 첫 집계 **17s → 0.32s**, 캐시 후 **4ms**. 앱 실행 3초 내 사용량 완비(런타임 로그로 검증).
- 빈 상태를 `ProgressView` 스피너 + 안내문으로 개선. usage 태스크 우선순위 `.background→.utility`.

진단 도구 추가: `--render <tab> <path>`(뷰를 PNG로 렌더, 레이아웃 확인용).

## [ADD] 세션별 컨텍스트 한도 사용량 표시

세션 관리의 핵심 기능 — 각 세션 행에 컨텍스트 윈도우 사용량 바 추가.

- **현재 컨텍스트** = 최신 assistant 턴의 `input + cache_read + cache_creation + output` (= 프롬프트+응답 크기). JSONL tail에서 추출(저비용).
- **한도 추론**: 모델 문자열에 `[1m]` 표기가 없어, tail에서 관측된 **최대 컨텍스트 > 200K이면 1M, 아니면 200K**로 추론(`SessionContext.inferWindow`). 200K를 초과한 적이 있으면 1M 세션이 확정되므로 안전.
- **UI**: `ContextBar` — 채움 비율 바(60%↓ 녹색 / 85%↓ 주황 / 그 이상 빨강) + `<used> / <window> · <pct>%` 라벨. 라이브 세션은 5초마다 tail 재파싱으로 실시간 갱신.
- 검증(`--probe` + 렌더): 여러 세션에서 컨텍스트/한도(200K·1M)/퍼센트가 정확히 표시됨. 200K 미초과 세션은 표준으로 보수적 추론.
- 진단 렌더 지원 위해 `SessionListView`에도 `scroll` 토글 추가.

## [ADD] 1M 정확 감지 · 컨텍스트 경고 · 메뉴바 아이콘 개선

1. **라이브 세션 1M 정확 감지**: 라이브 프로세스 env엔 단서가 없어, `~/.claude.json`의 프로젝트별 `lastModelUsage`에서 세션 현재 모델의 `[1m]` 키 존재 여부로 감지(`ConfigStore.projectUsesExtendedContext`). 200K 미초과 1M 세션도 잡힘. 관측 최대 > 200K(확정)과 OR 결합. 효과: 일부 세션의 한도가 `200K`→`1M`로 정정됨.
2. **컨텍스트 임계치 경고**: 라이브 세션의 컨텍스트가 윈도우의 **80%** 이상이면 메뉴바 아이콘이 경고 삼각형(주황)으로 전환(`AppState.contextWarning`/`peakLiveContextFraction`). 패널 헤더에도 `⚠︎ 컨텍스트 N%` 칩 표시.
3. **메뉴바 아이콘 명확화**: `sparkle` → **`terminal.fill`(세션=터미널) + 라이브 개수**. 세션을 나타냄이 직관적. 경고 시 `exclamationmark.triangle.fill`.
